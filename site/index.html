设计哲学

对过程激进（读/想/试全自主），对决策保守（删/改/花钱/不可逆才回来问）。

🧭 治理优先

声明式策略、硬/软边界、可解释裁决，安全由代码保证，不靠 prompt。

🔄 自主闭环

感知 → 规划 → 治理 → 行动 → 反思，Captain 自治 + 自动升级专家。

📡 事件脊椎

单向通知走总线，双向确认走回调，从第一天为多 agent 架构预留。

🧩 统一能力管线

工具 / Skill / GUI / 委托都收敛为 CapabilityCall，治理层单收口审查。

六层架构

脊椎式设计，每一层职责清晰、替换自由。

channels/ ← 外部接口（CLI / Web / 邮件 / 企微 / QQ / Slack） core/loop.py ← 编排器：只依赖接口的主循环（agent 心脏） governance/ ← ★ 治理层：统一收口审查（分寸感所在） capabilities/ ← 统一能力层：工具 / GUI / Skill / 委托 memory/ ← 工作记忆 + 混合长期记忆（SQLite + 向量） observability/ ← 全链路追踪 + 可回滚快照
