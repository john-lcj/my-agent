# weekly_report —— 让汇报体现"产出"而非"忙碌"

帮主人写周报/工作汇报时读本指南。汇报的读者是上级或协作方,他们想知道三件事:
**做成了什么、有没有风险要我介入、下一步是什么。**

## 标准结构

```
# 周报 · <姓名/团队> · <日期范围>

## 本周成果(Done)
- <交付物/结果 + 量化影响>(强调"完成"和"影响",不是"做了")

## 进行中(In Progress)
- <事项 + 当前进度% + 预计完成时间>

## 风险 / 需要支持(Blockers)
- <卡点 + 需要谁/什么帮助 + 影响>（前置,别藏在最后)

## 下周计划(Next)
- <按优先级列 3-5 项,与目标对齐>

## 数据 / 指标(可选)
- <关键指标本周变化>
```

## 写作原则

- **成果导向**:写"上线了 X,转化提升 3%",不写"做了 X 的开发"。让动词落在结果上。
- **量化**:能用数字就用数字(完成数、占比、耗时、指标变化)。
- **风险前置**:把需要上级决策/资源的卡点放显眼处,这是汇报最有价值的部分——别等出事才说。
- **对齐目标**:每项尽量挂到团队目标/OKR,让读者看到"为什么这件事值得做"。
- **简洁**:一屏读完。细节放链接,不堆在正文。
- **诚实**:没完成的别粉饰,写清原因和补救计划——可信度比好看更重要。

## 自查

- [ ] 上级能在 1 分钟内知道本周关键产出和有没有要他介入的事?
- [ ] 成果是否量化、是否体现影响而非动作?
- [ ] 风险/需要支持的事项是否清晰、前置?
- [ ] 下周计划是否聚焦、与目标对齐?
