# meeting_notes —— 从一堆讨论里,提炼出"谁该做什么"

整理会议纪要时读本指南。好的纪要不是逐字记录,而是**让没参会的人看完就知道结论和该做的事,
让参会的人看完就知道自己被分派了什么**。

## 标准结构(按此输出)

```
# 会议纪要 · <主题>
- 时间 / 参会人 / 缺席人

## 决议(Decisions)
- <做了什么决定 + 一句理由>（每条都是"已定"的事,不是讨论)

## 行动项(Action Items)
| 事项 | 负责人 | 截止 | 状态 |
|------|--------|------|------|
| ... | @某人 | MM-DD | 待办 |

## 待办讨论 / 悬而未决(Open Questions)
- <还没拍板、需要后续跟进的问题>

## 风险与依赖
- <可能阻碍的点 + 依赖谁/什么>

## 要点摘要
- <3-5 条关键信息,供快速回顾>
```

## 提炼原则

- **决议 vs 讨论**:只有"拍了板"的才进决议;还在争论的进"悬而未决"。
- **每个行动项必须有负责人和截止**。没有负责人的行动项 = 没人做。当场不明确就标"待认领"。
- **动词开头写行动项**:"产出 X 草案""约 Y 对齐",而不是"X 的事"。
- **去噪**:寒暄、跑题、重复表态都不进纪要。
- **量化**:把"尽快""差不多"换成具体日期/数字。

## 整理流程

1. 先抓**决议**和**行动项**(这是纪要的命脉),其余次要。
2. 给每个行动项补全负责人 + 截止;缺失的明确标出来,提醒会后确认。
3. 风险/依赖单列,便于跟踪。
4. 最后写 3-5 条要点摘要,放最上面或最下面供快速浏览。
